# SafeRoom v0.1.1

SafeRoom `0.1.1` hardens the credential and approval boundaries, makes failed
run evidence durable, and aligns public claims with the exact information the
CLI records. See [[CHANGELOG]], [[SECURITY]], and [[production-readiness]] for
the detailed change history, threat model, and certification evidence.

Acceptance-tested pre-version candidate:
`e458ab5f10feeff885b5f6828ebb1a31bfcbedac`. The final RC commit and tag are
recorded in [[production-readiness]] after the post-version certification run.

## Highlights

- `.env*` and `.saferoom/` paths are excluded at every directory depth during
  both audit collection and approval, including when a review patch is
  modified after collection.
- Adversarial coverage exercises protected-path recreation, tampered patches,
  renames, symlinks, spaces, binary content, and `.gitattributes` ambiguity.
- One-shot stdout and stderr stream to the terminal and `transcript.log`.
  Nonzero exits and interruptions retain reports, diffs, transcripts, and the
  observed exit status.
- Session IDs remain sortable and no longer collide when runs start within the
  same second. Expected configuration and Docker failures now provide concise,
  actionable guidance.
- CI covers Python 3.8 and 3.12, the local security suite, offline Docker,
  installer syntax, repository whitespace, and landing-page parsing.

## Install

```bash
git clone https://github.com/kascadeceo/saferoom
cd saferoom
sudo ./install.sh
```

SafeRoom is a single standard-library Python file. It supports Python 3.8+
and is Linux-first, with Debian/Ubuntu installer guidance. On macOS, install
and start Docker Desktop before running the installer. Other environments need
Python, Git, Docker, and a POSIX shell available.

## Audit semantics

For a one-shot run, SafeRoom records the exact submitted argument vector and
shell entrypoint, captures merged stdout/stderr in `transcript.log`, records the
changed-file list and full reviewable git diff, and stores the exit code in both
Markdown and JSON reports. It does not claim that the submitted shell string is
a trace of every child process.

For an interactive run, SafeRoom records shell history when the shell writes
it. Existing sessions created by older releases remain reviewable when their
`report.md` is present.

Approval evidence records the approver, UTC time, and SHA-256 of the exact
eligible patch. Approval independently rejects any `.env*` or `.saferoom/`
path, even if the stored patch was tampered with after review.

## Upgrade from v0.1.0

Pull or check out the `v0.1.1` release and rerun `sudo ./install.sh`. No data
migration is required. Existing local session directories remain local and can
still be reviewed; new runs add transcript and exit-status evidence.

## Known limitations

- Docker is the isolation layer. SafeRoom targets well-intentioned agents that
  could make catastrophic mistakes; it does not claim hostile-code or
  microVM-grade kernel isolation.
- Database-mutation capture and API-call interception are not included.
- One-shot evidence is an entrypoint plus captured output, not syscall-level
  command tracing.
- Hosted team history, repository policy, access governance, and evidence
  exports are planned SafeRoom Pro/Kascade services, not available CLI
  features. Evidence can support a compliance program but does not itself
  confer SOC 2, HIPAA, EU AI Act, or other regulatory compliance.
